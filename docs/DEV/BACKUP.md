# 备份与回退说明（BACKUP）

> 面向非技术使用者的操作说明。你不需要懂命令，只需要「双击脚本」。

## 一句话原理

所有改动都记录在本项目的 **Git 版本库**里。每次「备份」= 把当前改动存成一个存档点；
需要时可以「回退」到任意一个存档点。存档点有一个名字（标签），例如 `backup-20261011-153000`。

## 五个脚本（在 `scripts\` 目录里）

| 脚本 | 双击后会发生什么 | 什么时候用 |
| --- | --- | --- |
| `0-环境自检.bat` | 检查编译工具、依赖、目录是否齐全，只读不改 | 换机器 / 出问题排查时 |
| `1-一键测试.bat` | 编译 32 位与 64 位 Release，校验产物与导出表 | 每次改完代码想确认「能不能编过」 |
| `2-一键打包.bat` | 编译 + 加壳 + 生成可发给用户的分发包 zip | 想给别人试用时 |
| `3-一键备份.bat` | 把当前改动提交进 Git 并打一个时间标签 | **每次改动完成后都做一次** |
| `4-一键回退.bat` | 列出所有存档点，选一个把项目恢复回去 | 改坏了 / 想对比旧版本 |

## 推荐的日常节奏

1. 改代码（由开发方完成）。
2. 双击 `1-一键测试.bat`，看到「测试通过」。
3. 双击 `3-一键备份.bat`，输入一句本次改动的说明（例如「修复字体列表滚动」）。
4. 重复 1–3。

## 回退怎么做（放心，不会丢东西）

1. 双击 `4-一键回退.bat`。
2. 屏幕会列出所有存档点（标签 + 说明）。
3. 输入要回到的标签名，回车。
4. 脚本会**先把当前状态自动另存一个 `before-rollback-...` 标签**，再回退。
   → 即使回退错了，也能再回退回来。

## 备份存在哪

- 主备份：本项目根目录下的 `.git` 文件夹（**不要删除**）。
- 你无需手动复制文件；Git 已完整记录每一次改动。

## 注意事项

- 备份前不必手动整理文件，脚本会自动处理构建产物（它们不会被存档）。
- 不要删除 `.git` 目录，那会丢失全部历史。
- 若脚本提示「没有需要备份的改动」，说明当前没有新改动，属正常。
