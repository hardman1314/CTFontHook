# 功能档案：字符集智能预选 + 应用后重启提示（P1-1 / P1-2）

> 对应痛点：`USER_FLOW.md` 第 4 节 **P1-1**（必须自己判断游戏文本编码，选错就乱码）
> 与 **P1-2**（应用后不提示「可能需要重启游戏」）。
> 状态：✅ 已实现并通过编译验证（2026-10-11）。**未做真机验证。**

## 1. P1-1 字符集智能预选

### 背景

字体选择器顶部有一排「字符集药丸」（全部 / GBK / Shift_JIS / Big5 / 韩文 …）。
默认停在「全部」，玩家需自己判断游戏文本编码，选错会乱码或字体不生效。

DLL 本身已在游戏调用 `CreateFont` 时把编码写进 `Config::DetectedCharset`
（`src/hooks/internal/font_hooks_runtime.cppinc`）。这份检测结果此前只用于预览区渲染
（`state/font_picker_layout_geometry.cppinc` 的 `GetGameCharset()`），未用于预选。

### 方案

显示选择器时，若满足以下**全部**条件，则把药丸预选到与检测结果一致的项：

1. 用户尚未选定过字符集（`g_charsetSelectionSet == false`）；
2. 用户没有在配置里显式指定字符集（`Config::EnableCharsetReplace == false`）；
3. 检测结果已就绪（`Config::DetectedCharset != DEFAULT_CHARSET`）；
4. 检测结果能在药丸表里找到对应项。

预选成功后置 `g_charsetSelectionSet = true`，**之后不再自动干预**；用户手动点击药丸也会置位。

| 文件 | 位置 | 改动 |
| --- | --- | --- |
| `src/ui/internal/state/font_picker_state.cppinc` | `:290` | 新增 `g_charsetSelectionSet`。 |
| `src/ui/internal/input/font_picker_wndproc.cppinc` | `:11` | 新增 `PreselectCharsetFromDetection()`。 |
| 同上 | `WM_HOTKEY` 分支 | 显示选择器后调用 `PreselectCharsetFromDetection()`。 |
| 同上 | `HandleCharsetClick` | 用户手动选药丸时置 `g_charsetSelectionSet = true`。 |

### 已知边界

- 若选择器在游戏尚未调用 `CreateFont` 前就被唤出，检测结果仍是 `DEFAULT_CHARSET`，
  此时**不预选**（保持「全部」）；下次唤出若已检测到，再自动预选。
- 「字符集」药丸语义与「替换字符集」配置项一致：选「全部」= 不强制改写游戏原编码。

## 2. P1-2 应用后重启提示

### 背景

部分引擎会缓存已创建的字体，应用新字体后当前画面不刷新，玩家以为「没生效」。
指南「问题处理」里有一句说明（`paint_guide.cppinc` 的「仍未刷新」），但应用当下**无任何提示**。

### 方案

应用字体后，在预览区顶部显示一条**一次性提示条**，约 4 秒后自动消失：

> 已应用「<字体名>」；若游戏内未刷新，请重启游戏。

### 改动点（文件 : 行号）

| 文件 | 位置 | 改动 |
| --- | --- | --- |
| `src/ui/internal/state/font_picker_state.cppinc` | `:293` | 新增 `PICKER_APPLY_TOAST_TIMER_ID`、`APPLY_TOAST_MS`、`g_applyToastText`。 |
| `src/ui/internal/font_picker_font_list.cppinc` | `ApplySelectedFont()` 末尾 | 设置提示文案、启动一次性定时器、重绘预览区。 |
| `src/ui/internal/input/font_picker_wndproc.cppinc` | `WM_TIMER` | 命中提示定时器 → 清文案、停表、重绘预览区。 |
| `src/ui/internal/paint/font_picker_paint_preview.cppinc` | `PaintPreviewPanel()` 末尾 | 绘制提示条（最上层）。 |

### 已知边界

- 提示条覆盖预览区顶部约 4 秒，属「短暂遮挡」的有意取舍（需足够醒目）。
- 定时器仅在应用到已创建窗口时启动（`g_hWnd` 有效）。

## 5. P1-4 保存失败的用户可见提示（2026-10-11，复用本文档的提示条通道）

> 对应痛点：`USER_FLOW.md` 第 4 节 **P1-4「配置写盘失败对用户完全静默」**
> （典型场景：游戏装在 `Program Files`，当前进程无写权限）。
> 状态：✅ 已实现并通过编译验证。**未做真机验证。**

### 背景

`Utils::SaveConfig` 写盘失败时只 `Log("[Config] Failed to write INI file")`（`utils.cpp:926-928`），
用户完全无感：session 内字体看似已换（内存里的 `Config::*` 已生效），重启游戏却失效。

### 方案

让 `SaveConfig` 回报成败，把失败结果透传到「应用字体」路径，复用 P1-2 的提示条显示告警：

1. `Utils::SaveConfig` 由 `void` → `bool`（`framework.h` / `utils.cpp`）；
2. `SavePickerConfig()` 由 `void` → `bool`，透传结果（`font_picker_apply_config.cppinc`）；
3. `ApplySelectedFont()` 捕获结果：失败时提示条改用警示色 `COL_WARN` 并显示
   「保存失败：无法写入配置文件，重启游戏后会丢失（游戏目录可能无写入权限）。」

### 改动点（文件 : 行号）

| 文件 | 位置 | 改动 |
| --- | --- | --- |
| `src/framework.h` | `:115` | `void SaveConfig` → `bool SaveConfig`。 |
| `src/utils.cpp` | `:830 / :928 / :937` | 签名改 `bool`；失败 `return false`；末尾 `return true`。 |
| `src/ui/internal/font_picker_apply_config.cppinc` | `:94 / :112` | `SavePickerConfig()` 改 `bool`，`return ok`。 |
| `src/ui/internal/state/font_picker_state.cppinc` | `:245 / :297` | 新增 `COL_WARN` 与 `g_applyToastError`。 |
| `src/ui/internal/font_picker_font_list.cppinc` | `ApplySelectedFont()` 末尾 | 按 `configSaved` 选文案与错误标志。 |
| `src/ui/internal/paint/font_picker_paint_preview.cppinc` | 提示条绘制 | 颜色按 `g_applyToastError` 取 `COL_WARN`。 |
| `src/ui/internal/input/font_picker_wndproc.cppinc` | `WM_TIMER` | 清提示时复位 `g_applyToastError`。 |

### 有意不改

- 高级页（`ApplyMetricsConfig` / `ApplySpoofConfig` / `ApplyTextSubstitutionConfig` / `ApplyCodepageRedirectConfig`）
  的保存失败**仍保持静默**，本次只覆盖「应用字体」主路径。
- `dxlib_font_cache.cppinc:167` 的 `SaveConfig` 调用忽略新返回值，逻辑不变。

### 遗留
