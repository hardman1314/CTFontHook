# 功能档案：界面重构（设计稿复刻）

> 状态：**已完成**（批次 1 / 2 / 3 均已落地并通过编译验证；界面观感待主人真机确认）
> 目标：把 CTFontHook 字体选择窗口按 Figma 设计稿（《CT字体器》/《Main Content》）**严格复刻**为
> 「深海蓝」暗色面板，同时**保留全部既有功能**。

---

## 1. 背景与决策

- **来源**：项目主人在 Figma 中设计了一套专属 CTFontHook 的「字体选择调试器」界面，
  导出数据置于仓库 `设计图/`（`Main Content.json` 为真实窗口稿，`Text.png` 为列表区海报背景图）。
- **三项关键决策（用户确认）**：
  1. **复刻严格度 = 设计外观 + 保留全部功能**：外观严格按设计；但既有功能一个不丢
     （例：字符集药丸保留「韩文」；列表行保留「✓ 已应用 / ☆ 最近」徽章，仅按新配色重绘）。
  2. **窗口尺寸 = 默认 410×724，仍可缩放**（最小 380×660）。
  3. **列表背景图 = 由主人从 Figma 导出**（`设计图/Text.png`，343×412 RGBA）。
- **附加决策**：UI 整体缩放由「标题栏 A−/A+ 按钮」改为 **Ctrl+滚轮**；
  预览字号 A−/A+ **仅本次会话有效**（不写入 ini，默认 22px）。

## 3.7 真机反馈修复：海报背景跟随窗口缩放（2026-10-11）

- **现象**：主人拖动缩放窗口时，列表区海报背景**不跟随整体缩放**——窗口放大/缩小后海报仍是同一
  尺寸；且默认尺寸下**列表右侧露出一条约 42px 的空白**。
- **根因**：`paint/font_picker_paint_list_bg.cppinc` 的 `DrawListPoster` 把缩放帧**写死为设计稿常量**
  `frameW = 470 / frameH = 410`，而海报资源实为 **343×412** → `s = max(470/343, 410/412) = 1.370`
  → 海报恒定绘制成 **470×565 像素**，与窗口尺寸无关（锚在列表区左上、超出部分被列表裁掉）。
  窗口本身是跟随的（`WM_SIZE` 更新 `WINDOW_WIDTH/WINDOW_HEIGHT` 并重算 `g_uiScale`），
  列表行卡片底板也按行实尺寸生成——**只有海报这一处用了常量**。
- **改法**（1 文件 / 3 行 + 注释）：
  - `paint/font_picker_paint_list_bg.cppinc`：`frameW/frameH` 由常量 `470/410` 改为
    `listRc.right - listRc.left` / `listRc.bottom - listRc.top`，并加 `frameW/frameH <= 0` 早退；
    **缩放方式（CROP 覆盖）与锚点（列表区左上）保持不变**。
- **效果**（海报 343×412）：默认 512×905 → 列表区约 512×348 → `s≈1.49` → 绘制 **512×615**
  （横向正好铺满、纵向裁切）；最小 340×600 → 列表区约 340×236 → `s≈0.99` → 340×408。
  从此**始终铺满列表区并随窗口等比缩放**。
- **明确不改**：窗口底渐变、兼容设置面板、行卡片底板、海报资源 `res/list_bg.png` 与
  `LIST_BG_RESOURCE_ID`、布局常量与 reduced-model 缩放方式、热键与协议。
- **验证**：`scripts\1-一键测试.bat` → **4/4 通过**；真机需主人拖动缩放确认背景跟随、右侧不再露底。

## 4. 已知限制 / 风险

- GDI 无法完全复刻 Figma 的**斜向渐变**与亚像素值 → 统一用整数近似。
- 窗口圆角目前为「1px 圆角描边贴合方角窗口」（无原生边框）；后续如需真圆角需改用 Region。
- 海报缩放已改为**按列表区实时尺寸 CROP**（§3.7），锚点为**列表区左上**（如需角色居中可只改锚点）。
- **兼容设置下拉菜单为「窗口内叠加绘制」**：若面板超出窗口下沿会自动向上弹出；菜单只叠加显示，
  不改动其他组件。放大后个别纯手工定死的装饰矩形（如预览区 A−/22px/A+）比例略偏，属外观小瑕疵。
- **无法在本机做可视化验证**（原生 GDI 窗口，无浏览器/开发服务器）→ 观感确认依赖主人**真机验证**。
