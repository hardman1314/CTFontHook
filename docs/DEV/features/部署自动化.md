# 功能档案：部署自动化——独立 GUI 安装器

> 对应痛点：装 DLL 全流程**依赖用户手工操作**（判断架构 / 备份 / 复制 / 手动还原）。
> 状态：✅ 已实现并通过编译与打包验证（2026-10-11）。形态与范围经用户确认。

## 1. 背景与问题（自动化前的现状）

要让字体替换生效，玩家原本必须自己完成：

1. **判断游戏 EXE 是 32 位还是 64 位**（看架构猜），据此选 `32bit` 或 `64bit` 的 `winmm.dll`；
2. **手工备份**游戏目录里已有的 `winmm.dll`（如有）与 `FontHook.ini`；
3. **手工复制**对应位数的 `winmm.dll` 到游戏 EXE 同级目录；
4. 回退时**手工还原**：删掉放进去的 DLL、把备份改回原名。

四步全靠用户操作，小白极易在「第 1 步判断架构」就直接卡住。

## 2. 形态与范围（用户已确认）

- **形态**：独立的 **GUI 安装器 EXE**（C++ Win32，随发布包分发），不引入第三方安装框架。
- **范围**：**仅安装 / 卸载**（最小可用），不做在线更新、不做多游戏批量管理。

## 3. 安装器做了什么

安装器 `installer/main.cpp`：

| 能力 | 实现 | 位置 |
| --- | --- | --- |
| 自动识别 EXE 架构 | 读 DOS 头 `e_lfanew` → 校验 `PE\0\0` → 读 `IMAGE_FILE_HEADER.Machine`（`0x014C`=I386/32 位，`0x8664`=AMD64/64 位） | `ReadPeMachine` `:90` |
| 按架构选 DLL | `ArchSubDir()` → `32bit` / `64bit` | `:129` |
| 备份原文件 | 存入 `<游戏目录>\.CTFontHook\backup\` | `DoInstall` `:222` |
| 复制 DLL | 从**安装器所在目录**的 `32bit|64bit\winmm.dll` 复制到 EXE 同级 | `:241` |
| 写安装记录 | `<游戏目录>\.CTFontHook\manifest.ini`（含 `HadWinmm` / `HadIni` / `DllArch`） | `WriteManifest` `:154` |
| 卸载 / 还原 | 删掉安装进去的 `winmm.dll`；有备份则自动还原 `winmm.dll` / `FontHook.ini` | `DoUninstall` `:296` |
| 需要管理员权限 | 工程 `EnableUAC=RequireAdministrator`（游戏常在 `Program Files`，无写权限） | `CTFontHookInstaller.vcxproj` |

> **备份/还原契约**：所有备份与安装记录都集中在游戏目录的隐藏文件夹 `.CTFontHook\`
> （`backup\` 存原件，`manifest.ini` 记录是否备份过）。卸载**只依据** `manifest.ini` 判断是否需要还原，
> 因此「先装后卸」是自洽的；用户手工删除 `.CTFontHook` 即等同于放弃自动还原。

## 4. 发布包结构（`2-一键打包.bat` 产物）

```
CTFontHook-<版本>-<时间戳>\
├─ CTFontHook-Setup.exe     ← 双击即用（安装 / 卸载）
├─ 32bit\winmm.dll          ← 安装器按架构自动取用
├─ 64bit\winmm.dll
├─ 版本.txt
└─ 使用说明.txt             ← 首推「双击安装器」，手工步骤降级为附录
```

安装器按**自身所在目录**寻找 `32bit\` / `64bit\`，故解压后请保持目录结构（勿只单独拷出 EXE）。

## 5. 工程与脚本接入

## 6. 验证（均为实测）

- `scripts\1-一键测试.bat`：`[3/4]` 产出 `installer\bin\Win32\Release\CTFontHook-Setup.exe`（116736 B，PE Machine=`0x014C` 即 32 位，含 `requireAdministrator` 清单）。
- `scripts\2-一键打包.bat`：产出的 zip 内含 `CTFontHook-Setup.exe` 与 `32bit\`、`64bit\` 双架构 DLL、`使用说明.txt`、`版本.txt`。
- **架构判定算法**已用临时探针校验：`System32\notepad.exe`→`0x8664`（64 位）、
  `SysWOW64\notepad.exe`→`0x014C`（32 位）、本项目 x64/x86 `winmm.dll` 各自匹配，全部正确。

## 7. 已知问题 / 遗留

- **未做真机安装验证**：尚未对真实游戏目录执行「安装→启动游戏→卸载还原」的完整闭环。
- 安装器为 **32 位** EXE（可在 32/64 位 Windows 上运行）；因需读目标 PE 头并复制文件，未受 WOW64 重定向影响。
  注意：若在 32 位安装器进程里读取 `System32` 下文件会被重定向到 `SysWOW64`，但本工具读取的是**用户选定的游戏 EXE**，不受影响。
- 未做代码签名（仅写入开发者版本信息，未购买证书），Windows SmartScreen 仍可能提示「未知发布者」。
- 卸载仅撤销「本安装器自己写下的记录」；不清理游戏运行后自行生成的 `FontHook.ini`（除非安装时备份过）。

## 8. 迭代：修窗口显示 + 版本信息（任务 B1+B3）

- **问题**：高分屏下提示文字被裁剪。根因是 `SetProcessDPIAware()` 让系统字体随 DPI 放大，而布局用固定像素。
- **修复**：新增 DPI 感知缩放 `g_dpi` / `S(int)`；控件坐标与字体（显式 `CreateFontW`）全部经 `S()` 计算；
  提示改为两行；窗口客户端 620×450 → 760×626（B2 后尺寸见第 9 节），并支持调整大小（日志区自适应）。
- **版本信息**：新增 `installer/version.rc`（`CompanyName=HardMan_Official`、`ProductName=CTFontHook`、
  `FileVersion=0.1.0.0`）。实测 `VersionInfo` 已写入 EXE。

## 9. 迭代：多游戏字体管理器（任务 B2）

面向「多个游戏都要改字体」的需求，安装器从「单游戏工具」升级为多游戏集中管理。

- **中央清单**：`%APPDATA%\CTFontHook\games.ini`（UTF-16LE + BOM，节 `[GameN]`，键
  `Name` / `Exe` / `Dir` / `DllArch` / `InstalledAt`）。安装成功后自动登记（按目录去重）。
- **列表**（`SysListView32`，报告视图）：列 = 游戏 / 目录 / 架构 / 当前字体 / 状态。
  - 「当前字体」读取该游戏目录下 DLL 写出的 `FontHook.ini`（UTF-8 + BOM）里的 `FontNameW`；空则显示「（默认字体）」。
  - 「状态」依据 `<游戏目录>\.CTFontHook\manifest.ini` 是否存在：`已安装` / `未安装`。
- **按钮**：`卸载 / 还原`（对选中项，恢复备份或移除 winmm.dll）、`打开目录`、`移除记录`（需先卸载）、
  `刷新`、`手动登记游戏…`（为老用户补登记已装好补丁的游戏）。
- **界面长度**：客户端 760×626；清单行 `安装` 与列表/操作按钮分离。
- **工程**：`<Link><AdditionalManifestDependencies>` 引入 Common-Controls v6（已验证嵌入清单同时含
  `requireAdministrator` 与 Common-Controls 依赖）；`#pragma comment(lib, "comctl32.lib" / "shell32.lib")`。
- **验证**：`scripts\1-一键测试.bat` `[1/4]`~`[4/4]` 全通过；`mt.exe` 提取嵌入清单确认含两项。
- **遗留**：未在真机（真实游戏目录）跑「多游戏安装/切换/卸载」闭环；中央清单写在当前用户 `%APPDATA%`，
  若以「其他管理员账户」提权运行，清单会落到该账户目录（家用场景通常为同一账户，不受影响）。
