# 功能档案：配置写入保留注释（P2-6）

> 状态：**已实现，4/4 编译通过，待真机验证**　最后更新：2026-10-11

## 1. 问题（P2-6）

上游实现里，`FontHook.ini` 每次保存都被**全量重写**：

- `Utils::SaveConfig`（`src/utils.cpp`）从 `Config::*` 重新拼出一份完整文本，
  再用 `CreateFileW(..., CREATE_ALWAYS, ...)` **覆盖写**。
- 拼出来的文本只包含程序已知的键，因此玩家在 ini 里手写的
  **注释（`;` / `#` 开头的行）、空行、以及程序不认识的键**，保存一次就全没了。

保存发生在「应用字体 / 切换开关 / 改排版数值 / 勾选默认隐藏」等所有落盘路径
（`ui/internal/font_picker_apply_config.cppinc:112`、`hooks/.../dxlib_font_cache.cppinc:167` 等）。

## 2. 结论与方案

全项目**只有 `Utils::SaveConfig` 一处**写该文件，所以只需改这一个函数：
把「覆盖写」改为「**与旧文件合并**」——受管键就地更新，其余内容原样保留。

读取端（`LoadConfig` / `ParseIni`）**完全不动**：`ParseIni` 本就按「扁平键值、忽略注释/空行/节头」解析，
所以保留注释不影响任何读取语义。

## 3. 实现要点（全部在 `src/utils.cpp`）

### 3.1 新增两个 static 辅助函数

- `ReadIniTextFile(iniPath)`：读回现有 ini 原文（去 UTF-8 BOM）。
  文件不存在 / 读失败 → 返回空串（此时按「首次写入」处理）。
- `IniLineKey(line)`：取 `Key=Value` 的键名；注释 / 空行 / 节头行返回空串
  （规则与 `ParseIni` 一致：`';'` `'#'` `'['` 开头或没有 `=` 视为非键值行）。

### 3.2 `SaveConfig` 的合并逻辑

1. 先照旧把受管键拼成文本 `out`（键名、值、顺序**与既有实现完全一致**）。
2. 把 `out` 解析成 `(key, 完整行)` 列表 `managedLines`（首行 `[FontHook]` 会被 `IniLineKey` 跳过）。
3. 读旧文件：
   - **不存在**：`merged = out` → 与既有行为**逐字节一致**。
   - **存在**：逐行输出旧文件——
     - 命中受管键 → 用新值那行替换（**仅首次**）；
     - 重复出现的受管键 → 丢弃旧行（保证写回的新值生效）；
     - 其它（注释 / 空行 / 未知键 / 节头）→ **原样保留**；
     最后把旧文件里**缺少的受管键**补到末尾。
4. 仍用 `CREATE_ALWAYS` + UTF-8 BOM 写回（编码、换行不变）；写失败仍返回 `false`。

## 4. 明确不改

- `LoadConfig` / `ParseIni` / `FindIniValue` / `AppendIni*` / `GetIniPath` 及读取语义。
- ini 的键名、值格式、UTF-8 BOM、CRLF 换行。
- 其它任何文件。

## 5. 验证

- `scripts\1-一键测试.bat` → **4/4 通过**（x64 / Win32 DLL + 安装器 + 双架构导出校验）。
- 逻辑核对：无注释文件走 `merged = out` 分支，输出与旧实现逐字节一致；
  带注释样例按「行序保留 + 受管键就地替换 + 缺失补末尾」推演正确。

## 6. 待办 / 已知限制

- **真机验证未做**（本机无 GUI）：需进游戏触发一次保存，再打开该游戏的 `FontHook.ini`
  确认手写注释 / 未知键确实保留。
- 已知边界：受管键若写成**行内注释**（`Key=Value ; note`），整行会被替换、行内注释不保留
  （`ParseIni` 本就不支持行内注释，不影响读取语义）。
- 若 ini 因被独占占用导致**读**失败，会退回「首次写入」行为（注释丢失）——
  与旧行为一致，不构成回归。
