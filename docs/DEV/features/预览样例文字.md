# 功能档案：预览样例文字可编辑（P2-2）

> 对应痛点：`USER_FLOW.md` 第 4 节 **P2-2「预览看不到游戏自身文字」**——
> 预览区只有两行硬编码样例文字，玩家无法用「游戏里的实际文本（人名 / 对话 / 生僻字）」
> 检验所选字体的渲染效果，只能盲选。
> 状态：✅ 已实现并通过编译验证（2026-10-11）。**未做真机验证。**

## 1. 背景与方案选型

### 背景

预览区第 1 行为固定串「测试文字 Sample Text」（`paint/font_picker_paint_preview.cppinc:61` 附近，
第 2 行为固定假名 + 数字）。玩家想验证某个生僻字 / 游戏专有名词在候选字体下是否好看、是否缺字，
**没有任何入口**。

### 两条路线（审计后二选一）

- **路线 A（本次采用）**：让第 1 行样例文字**可由用户行内编辑**，并持久化到 `FontHook.ini`。
  风险低、改动小、复用既有「行内编辑框」模式。
- **路线 B（本次未做，降级到 P3）**：Hook 游戏自身的 `TextOut` / `ExtTextOut` / `DrawText`，
  把游戏实际绘制的字符串「自动抓」进预览区。
  风险高——需在渲染热路径上截获字符串，涉及多字节/宽字符编解码、绘制频率与线程安全，
  一旦出错会**直接影响游戏画面**，收益却与路线 A 相近。故本次不做。

## 2. 方案（路线 A）

### 交互

1. 鼠标悬停预览区样例文字 → 该行右上角显示提示「点击此处可编辑样例文字」（高亮为强调色）。
2. 单击样例区 → 在样例文字位置弹出**行内输入框**（EDIT 子窗口），预填当前样例（未自定义时为内置默认）。
3. 输入后：
   - `Enter` → 提交，写入配置（键 `PreviewTextW`）并立即重绘预览；
   - `Esc` → 取消，恢复原样；
   - `Tab` → 透传给主窗口（切换页面）；
   - 点窗口别处（失焦 `EN_KILLFOCUS`）→ 视同提交。
4. 清空输入框并提交 → `PreviewTextW` 为空串，预览回退到**内置默认样例**（不会显示空白行）。

### 持久化

写入 `FontHook.ini` 的 `[FontHook]` 段，键 `PreviewTextW`（UTF-8，复用既有 `AppendIniText` / `FindIniValue`）。
下次启动游戏自动加载；空值 = 用内置默认样例。

## 4. 复用与边界

- **复用既有模式**：完全照搬 `input/font_picker_metric_edit.cppinc` 的行内编辑框套路
  （`CreateWindowExW(L"EDIT")` + `SetWindowLongPtrW(GWLP_WNDPROC)` 子类化 + `Enter`/`Esc`/`Tab` 约定 +
  `EN_KILLFOCUS` 提交）。差异仅在于提交目标是全局配置 + 写盘，而非 `Config::*` 单个数值。
- **`Tab` 透传**：编辑框内 `Tab` 通过 `PostMessageW(GetParent(hWnd), ...)` 转交主窗口，保持「Tab 切页」不变。
- **失焦提交的竞态**：`g_previewTextEditClosing` 标志 + 先置 `g_hPreviewTextEdit = NULL` 再 `DestroyWindow`，
  避开 `DestroyWindow` 触发的 `EN_KILLFOCUS` 二次提交（与 metric 编辑同源处理）。
- **未自定义时**：`PreviewTextW` 为空 → 预览第 1 行显示内置默认「测试文字 Sample Text」，
  与改动前视觉一致（老用户无感知）。

## 5. 明确不改

- 第 2 行（假名 + 数字）**保持固定**，不可编辑——它是「字形覆盖 / 字宽」的稳定基准，改动会削弱可比性。
- **未引入路线 B**（Hook 游戏绘制字符串）——风险与收益不匹配，降级到 P3 再评估。
- 未改预览字体、行高、对齐等既有绘制逻辑（除第 1 行取串来源外）。
